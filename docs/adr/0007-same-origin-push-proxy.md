# ADR-0007 — 브라우저는 API 를 직접 부르지 않는다 (같은 출처 프록시)

- 상태: **Accepted**
- 날짜: 2026-09-08
- 관련 작업: T-117 (웹 구독 UI)
- 관련 결정: [ADR-0006](0006-web-push-first.md)

## 맥락

T-117 이전까지 웹은 **서버 컴포넌트에서만** API 를 불렀다 (`lib/api.ts`,
컨테이너 내부 주소 `http://api:8000`). 브라우저는 API 를 전혀 몰랐고,
그래서 CORS 설정이 필요 없었다.

푸시 구독은 이 전제를 깬다. `PushSubscription` 은 **브라우저 안에서만** 만들어지므로
서버 컴포넌트가 대신 만들 수 없다. 어떤 식으로든 브라우저에서 나가는 요청이 생긴다.

또 서비스워커(`pushsubscriptionchange`)도 구독을 다시 등록해야 하는데,
서비스워커에는 페이지의 환경변수도 세션도 없다.

## 선택지

### A. API 에 CORS 를 연다

`CORSMiddleware` 에 웹 출처를 허용 목록으로 넣는다.

- 요청이 한 번에 끝난다 (프록시 홉 없음).
- 허용 출처를 **환경마다** 관리해야 한다 — 로컬·스테이징·운영·미리보기 도메인.
- 목록이 어긋나면 **구독만 조용히 실패한다.** 나머지 화면은 서버 렌더라 멀쩡해서,
  운영자는 사이트가 정상이라고 본다. 사용자는 알림이 안 온다고만 느낀다.
- 브라우저가 API 오리진을 알아야 하므로 `NEXT_PUBLIC_*` 로 빌드에 박힌다.
  주소가 바뀌면 다시 빌드해야 한다.

### B. 웹서버에 같은 출처 프록시를 둔다 (채택)

`app/api/push/*` 라우트 핸들러가 받아 `API_BASE_URL` 로 전달한다.

- CORS 설정이 아예 필요 없다. 관리할 목록도, 어긋날 목록도 없다.
- 서비스워커가 `/api/push/*` 를 그냥 부를 수 있다 (같은 출처).
- API 를 외부에 노출하지 않고도 웹이 동작한다.
- 홉이 하나 늘지만 **구독은 사용자당 몇 번**이라 지연이 의미 없다.

### C. Next.js 서버 액션

Next 문서의 PWA 가이드가 쓰는 방식이다.

- 서비스워커에서 부를 수 없다 (`pushsubscriptionchange` 경로가 막힌다).
- 구독 저장 로직이 웹 앱으로 흘러간다. 저장소는 API 의 책임이다.

## 결정

**B — 같은 출처 프록시.**

결정적인 이유는 성능이나 결합도가 아니라 **실패 방식**이다.
A 의 실패는 조용하고 환경별로 다르게 나타나며, 하필 이 제품이 유일하게
놓치면 안 되는 기능만 망가뜨린다. B 에는 그 실패 경로 자체가 없다.

프록시는 상태 코드와 본문을 **바꾸지 않고 흘려보낸다** (`lib/proxy.ts`).
단 하나 예외가 API 연결 실패인데, 이때 502 JSON 을 만들어 준다 —
그냥 던지면 Next 가 HTML 오류 페이지를 내보내고 클라이언트의 `res.json()` 이
파싱 오류로 바뀌어 진짜 원인을 가린다.

## 결과

- `apps/web/lib/proxy.ts`, `apps/web/app/api/push/{public-key,subscribe}/route.ts` 추가
- API 에 CORS 미들웨어를 **추가하지 않는다**
- 웹이 API 를 부르는 경로가 두 개가 된다: 서버 컴포넌트(`lib/api.ts`)와
  프록시(`lib/proxy.ts`). 둘 다 `API_BASE_URL` 하나를 본다

## 재검토 조건

- iOS 네이티브 앱(M4+)이 붙으면 그쪽은 프록시를 쓸 수 없다.
  다만 네이티브에는 CORS 가 없으므로 이 결정과 충돌하지 않는다
- 웹과 API 를 다른 도메인으로 분리 운영하게 되고, 브라우저에서 부를 API 가
  구독 말고도 여러 개로 늘어나면 그때는 A 를 다시 본다

## 현재 구현 보충 — 2026-09-11

보안 검증을 거친 요청만 전달하며 중계 응답은 no-store, 내부 API 요청은 본문 수신까지 10초 제한이다.
구독 POST/DELETE는 JSON·본문 8 KiB/5초·동일 출처 검사를 거친다. 이 검증에서 생성하는 오류는
API에 요청하지 않고 웹에서 반환한다. RSS/ICS도 `app/v1/{feed.rss,releases.ics}/route.ts`의
고정 경로로 중계한다. 범용 `/v1/*` 프록시는 없고 관리자 API도 공개하지 않는다.
`API_BASE_URL`은 내부 호출, `PUBLIC_WEB_URL`은 공개 링크용이며 `PUBLIC_API_URL`은 사용하지 않는다.
