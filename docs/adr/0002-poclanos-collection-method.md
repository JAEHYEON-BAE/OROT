# ADR-0002: 포크라노스 수집 방식 결정

- **상태**: **Accepted** — 2026-08-20 결정
- **결정**: **서버 렌더링된 상품 상세 페이지 + ID 열거.**
  헤드리스 브라우저도, 내부 API 호출도 사용하지 않는다
- **관련**: 블루프린트 §2.2, §3.1, §3.4 / T-015, T-016
- **근거 문서**: [`docs/adapters/poclanos.md`](../adapters/poclanos.md)

---

## 1. 배경 — 그리고 초회 조사의 오류

초회 조사에서 다음과 같이 결론냈다.

> 포크라노스 스토어는 CSR 이라 `curl` 수집이 불가능하다. 헤드리스 렌더링 또는 내부 API 호출이 필요하다.

**이 결론은 틀렸다.** 목록 페이지(`/shop`)만 확인하고 **상품 상세 페이지를 확인하지 않았기 때문이다.**
목록이 클라이언트 렌더링이라는 사실로부터 사이트 전체가 그렇다고 일반화한 것이 오류였다.

상품 상세 페이지(`/shop/products/<id>`)는 **서버 렌더링된다.**
`__NEXT_DATA__` 의 `props.pageProps.product` 에 필요한 데이터가 전부 들어 있다 —
상품명, 가격, 재고, 판매 상태, 이미지, 상품 종류.

> **교훈**: "JS 렌더링 필요 여부"는 사이트 단위가 아니라 **페이지 종류 단위**로 판단해야 한다.
> 블루프린트 §3.2 조사 체크리스트 4번("`curl` 결과에 상품명이 포함되는지")을
> **목록·상세 각각에 대해** 수행하도록 §3 을 보강할 것을 권한다.

## 2. 결정

| 항목 | 내용 |
|---|---|
| 수집 방식 | 일반 HTTP GET (`httpx`) + `__NEXT_DATA__` JSON 파싱 |
| `requires_javascript` | `False` |
| 상품 발견 | `product_id` 순차 열거 (목록·사이트맵에 상품 URL 이 없음) |
| 최초 백필 | `id = 1..100`, 0.5 req/s 로 약 3분, 1회 |
| 정상 운영 | 최대 알려진 ID + 1 부터, 연속 5회 미발견 시 중단 (주기당 약 5요청) |
| 제외 대상 | `productType == "DATE_TICKET"` (리스닝 세션 티켓) |

## 3. 채택하지 않은 대안

### A. 헤드리스 브라우저 (Playwright)

**불필요해졌다.** 상세 페이지가 서버 렌더링이므로 브라우저를 띄울 이유가 없다.
collector 이미지에 Chromium 을 넣는 비용(약 300~400MB)과 운영 부담을 얻는 것이 없다.

> 참고: 초회 ADR 은 이 안을 "어댑터 인터페이스 변경이 필요한 큰 변경"으로 서술했으나 이 또한 부정확했다.
> 블루프린트 §3.1 에는 이미 `requires_javascript: bool` 이 있고, §2.2 는
> "Playwright — JS 렌더링 필요한 소스에만 선택적 사용"을 명시하고 있다.
> **즉 A 는 원래 블루프린트가 예정한 선택지였다.** 다만 이 소스에는 필요가 없다.

### B. 내부 API 직접 호출

**필요 없으므로 채택하지 않는다.**

논의 경과를 남겨 둔다. b.stage 의 상품 XHR 엔드포인트는 인증이 필요 없고 공개 스토어를 위한 것이라,
"이것을 호출하는 것이 정말 문제인가"는 제기할 만한 물음이었다. 서버 부하만 보면
JSON 1회 요청이 페이지+에셋 전체를 받는 것보다 **가볍다**는 반론도 성립한다.

그러나 상세 페이지 역시 **요청 1회**로 같은 데이터를 주므로 그 이점이 사라진다.
남는 것은 비용뿐이다.

- 블루프린트 §3.4 "비공개 내부 API 역공학 금지"를 완화해야 한다 — **얻는 것 없이 규칙만 무른다**
- 문서화되지 않은 엔드포인트는 호환성 약속이 없다. 공개 페이지 경로가 계약에 더 가깝다
- 네트워크 탭을 뒤져 엔드포인트를 알아내는 행위 자체가 그 조항이 겨냥한 대상이다

**얻는 것이 없을 때는 더 보수적인 쪽을 택한다.** §3.4 는 원문 그대로 유지한다.

### C. 소스 제외

바이닐을 실제로 판매하고 있음이 확인되었고(예: `id=71`, LP, 52,000원),
수집 비용도 낮으므로 제외할 이유가 없다.

## 4. 이 결정의 약점

정직하게 남겨 둔다.

- **ID 열거는 투박하다.** 우회 행위는 아니지만(공개 페이지를 순번대로 요청할 뿐),
  목록 API 를 쓰는 것보다 요청 수가 많다. 카탈로그가 100건 미만이고 증분 조회가 주기당 5요청이라
  현재 규모에서는 문제되지 않는다. **카탈로그가 크게 늘면 재검토한다**
- **삭제 감지가 늦다.** 중간 ID 가 사라져도 열거 대상이 아니면 모른다.
  블루프린트 §4.5 의 `DELISTED`(3회 연속 미발견)로 커버한다
- **표본이 3건뿐이다.** `saleStatus` 의 전체 값 목록을 모른다.
  알 수 없는 값은 `UNKNOWN` 처리하고 로그를 남긴다 (CLAUDE.md §2 규칙 5)

## 5. 남은 선행 조건

**이용약관 미확인.** b.stage 플랫폼 약관과 포크라노스 스토어 약관이 별개일 수 있다.
사람이 브라우저로 확인해야 하며, 자동 수집 금지 조항이 있으면 소스를 제외한다.
**T-016 착수 전 해소 필요.**
